# Synthetic control-pair generation + QA (paired edit LoRAs)

## Problem

Paired edit-LoRA training needs controls that are the target image with the
effect removed and NOTHING else changed. Full-frame generative removers
(nano-banana) re-render the whole image, introducing systematic drift:
pose/gaze straightened toward camera ("frontal-ization"), mirror-flipped
head direction (chirality lottery), framing/zoom changes, background or
color-grade shifts. Systematic drift trains the LoRA to alter identity/pose
along with the edit — the classic edit-LoRA failure mode.

## Trigger conditions

- Controls generated by instruction-editing the targets (removal direction)
- QA reports: "control gaze straightened", "head faces opposite direction",
  "control zoomed in / crown clipped", "background lighter/darker",
  "grade warmer/cooler"
- Vision-QA verdicts flip-flop about target-vs-control panels across rounds

## Solution

**Remover choice:** nano-banana (`gemini-3-pro-image-preview`) beat fal's
`fal-ai/qwen-image-edit-2511` base for removal — qwen re-framed portraits
entirely (measured: border-ring MAE 56 vs 43). Verify with a 1-image A/B
using region pixel stats before batching, but expect nano-banana to win.

**Batch pattern** (see `scripts/sununguro_make_controls.py`):
resumable, per-stem `EXTRA` instruction dict for targeted regen, cover-crop
output to exact target dims, side-by-side QA pair per image.

**The pose-failure mitigation ladder** (cheapest first; stop when QA passes):
1. **Pilot gate** — 1 image, full QA, before any batch.
2. **Base-prompt hardening** — explicit "same photograph, pixel-aligned,
   never straighten/re-center the head, never zoom" language. Fixes most.
3. **Per-stem targeted instruction** — name the specific failure ("keep the
   near-black background", "remove hardware from EVERY figure including
   cropped edge figures"). One targeted regen fixes ~half of failures.
4. **Deterministic flip** — if a render is correct but mirror-flipped,
   horizontally flip the FILE instead of re-rolling (verify background is
   near-symmetric via corner pixel stats first). Roll variance on
   pose axes is brutal (~1 in 4-5 renders averted correctly); don't chase
   it with re-rolls.
5. **Artist picks a base + micro-edit** — show ALL versions; the artist may
   accept a render QA rejected. Then do a minimal region edit (e.g. eyes
   only, using the target as gaze reference: "change ONLY the eyes to look
   in the same direction as image 2"). Verified working.
6. **Region-inpaint fallback** — segment the effect (Gemini segmentation) +
   `fal-ai/qwen-image-edit/inpaint` (requires prompt, image_url, mask_url);
   pose preserved by construction. Reserve for when generation keeps losing.

**What does NOT work:** multi-image pose-match ("redraw image 1's head to
match image 2's pose") — gemini-3-pro-image returns the content image
essentially unchanged. Chirality words ("left"/"right") in prompts are
ambiguous between viewer- and subject-relative and cause mirror errors.

## QA methodology (the part that failed silently)

- **Banner-label every QA composite** ("LEFT = TARGET … RIGHT = CONTROL").
  Unlabeled whole-pair vision reads misattributed panel sides repeatedly,
  producing WRONG regen instructions (a background was "fixed" to match the
  misread side).
- **Numeric pixel stats decide grade/background questions** — corner/band
  means and R−B warm-spread, not adjectives. A "cool desaturated" read was
  numerically neutral; the "fix" overcorrected to sepia.
- **Mirror-trio test for head direction**: read [target | control |
  mirrored-control]. A genuinely turned head reads opposite-facing when
  mirrored; control ≈ mirrored-control ⇒ the control is frontal.
- **One QA agent, serial reads, resumed across rounds** (SendMessage) —
  keeps calibration and lets it compare against earlier rounds.
- **Hair/invented-region diversity check**: when the removal invents hair or
  clothing, assign per-stem varied styles — uniform invented hair teaches
  "effect inputs have short hair". Only diversify stems where the region is
  truly invented (real hair visible in the target must stay).

## Versioning (non-negotiable)

Before ANY overwrite of a generated asset, rename the existing file to
`<stem>.v<N>.png.bak` (script does this automatically now). A re-roll once
destroyed the only correctly-posed render, which then had to be recovered
from a 700px QA composite. Keep `.bak` files OUT of the training control
folder (move to `qa/control_versions/`).

## Verification

Final gate is two-layer: QA agent passes all pairs (removal complete,
identity, pose/gaze, scene — with pixel stats), THEN the artist eyeballs
the pairs in Preview. The artist's eye outranks the rubric in both
directions (rejected a QA-passed control; accepted a QA-rejected one).

## Notes

- Gemini 2.5-flash segmentation on 1024px images can 504 at 120s timeout —
  use 768px input, 240s timeout, retry, fall back to 2.5-pro.
- ~$0.13/render at 2K; a 10-image set with the full ladder cost ~25 renders.
- Reference implementation: `scripts/sununguro_make_controls.py` (this repo).
